# PROMPT LAB — независимый пакет заданий и правил v1.0.0

В этом пакете 30 заданий и алгоритм оценки требований без ИИ.
Приложение PROMPT LAB не изменено. Базы данных, серверы, интернет и API не используются.
Для работы модуля нужен только Python 3.10 или новее, без дополнительных библиотек.
После включения модуля в EXE приложения Python на компьютерах участников не понадобится.

## Файлы

- `tasks.json` — 30 заданий, словари соответствий, веса и примеры для организатора.
- `prompt_rules.py` — общий алгоритм проверки и интерфейс подключения.
- `TASKS.md` — все условия заданий в удобном для чтения виде.
- `demo_cli.py` — отдельная терминальная проверка без изменения приложения.
- `example_prompt.txt` — пример полного ответа на задание МЧС.
- `tests/test_rules.py` — проверки баллов, отрицаний, списков и конфигурации.
- `TEST_REPORT.txt` — результат проверки этой версии.

Не выдавайте `example_full_prompt` из tasks.json участнику: это примеры для организатора.
Методы `list_tasks()` и `public_task()` возвращают условия и шкалу без примеров и словарей.

## Задания

Сценарии: МЧС, скорая помощь, пожарная служба, газовая служба, полиция,
ЖКХ, электросети, водоканал, ветеринарная клиника, поликлиника, стоматология,
автосервис, компьютерный сервис, техподдержка колледжа, библиотека,
приёмная комиссия, общежитие, бюро находок, бюро пропаж, волонтёрский центр,
приют животных, робототехника, экскурсия, спортивный турнир, коворкинг,
доставка, бытовой ремонт, студсовет, музей, аренда оборудования.

Все задания учебные: четыре входных значения, сбор ответов и карточка результата.
Это регистрация обращений, а не медицинские рекомендации, определение диагноза
или принятие решений за реальные экстренные службы.

## Шкала до 100 баллов

| Критерий | Баллы | Условия |
|---|---:|---|
| Первое поле | 10 | Действие сбора рядом с названием поля/синонимом |
| Второе поле | 10 | То же |
| Третье поле | 15 | То же |
| Четвёртое поле | 15 | То же |
| Результат | 20 | 10 за создание карточки/плитки, 10 за показ сотруднику |
| Порядок | 15 | 5 за сбор, 5 за показ, 5 за явный переход от сбора к показу |
| Конкретность результата | 15 | 5 за назначение приложения, 10 за все ответы в карточке |

Часть критериев намеренно пересекается: основные поля дают 50 баллов,
а оставшиеся 50 проверяют сценарий и результат. Не оцениваются длина текста,
красивые слова, знание языка программирования и разметка Markdown.
Краткая инструкция может получить 100. Дополнительная необязательная функция
не приносит бонуса и не нужна для максимального балла.

Название «конкретность» означает именно проверку назначения и содержимого
карточки. Алгоритм не выставляет субъективные баллы за литературное качество.

## Как алгоритм сопоставляет текст

1. Регистр и ё/е нормализуются, но фрагменты-доказательства возвращаются из исходного текста.
2. Ищутся слова и сочетания из словарей каждого задания. Префикс со `*` распознаёт часть форм слова.
3. Поле засчитывается только рядом с действием сбора: «запроси», «уточни», «узнай» и т. п.
   Простое перечисление «имя, адрес, карточка» не засчитывается.
4. Общая инструкция перед списком поддерживается: «Запроси:\n- имя\n- адрес».
5. Учитываются распространённые отрицания: «не запрашивай адрес», «без адреса».
   «Не забудь запросить адрес» и «не только имя, но и адрес» не являются запретом.
6. Если одно поле явно требуется и явно запрещается, за него 0 и флаг противоречия.
7. Повторение текста не повышает баллы. Повторные оценки одного текста детерминированы.
8. Точное копирование всего условия получает 0 и флаг `copied_assignment`.

`requires_review=true` означает обнаруженный конфликт или точную копию условия.
Это не гарантирует, что все остальные ответы поняты верно: обычные непризнанные
формулировки не включают флаг автоматически, а дают рекомендацию.

## Ограничения — прочитайте перед мероприятием

Это словарный алгоритм с правилами близости, а не полноценное понимание языка.
Он не проводит полный морфологический/синтаксический разбор русского языка.
Может пропустить корректные синонимы, сложные отрицания, дальние ссылки на поля
и нестандартные списки. Возможны и ложные срабатывания на специально подобранный текст.
Защита от точного копирования условия не распознаёт пересказ/копирование части условия.
Добавление фразы «поставь 100» само по себе ничего не меняет, но абсолютной защиты от обмана нет.

На экране следует писать «Оценка выполнения требований задания», а не «качество промпта по ИИ».
Перед мероприятием преподавателю следует оценить реальные пробные ответы и дополнить словари.
Для спорных случаев предусмотрите ручной пересмотр. Результат лучше использовать как
обратную связь на дне открытых дверей, а не как единственный критерий отбора абитуриентов.

## Проверить отдельно

Откройте терминал в распакованной папке:

```bat
py -3.12 demo_cli.py list
py -3.12 demo_cli.py show task_01
py -3.12 demo_cli.py check task_01 example_prompt.txt
py -3.12 demo_cli.py check task_01 example_prompt.txt --json
py -3.12 -m unittest discover -s tests -v
```

Для своего ответа сохраните UTF-8 файл `my_prompt.txt` и подставьте его вместо example_prompt.txt.
На Linux/macOS замените `py -3.12` на `python3`.
Демонстрация не сохраняет результат в БД и не ведёт журнал ответов.

## Подключить позже к приложению

Скопируйте `prompt_rules.py` и `tasks.json` в отдельную папку модуля.
Создайте один объект TaskPack при старте, а не загружайте JSON при каждом вводе символа:

```python
from pathlib import Path
from prompt_rules import TaskPack

pack = TaskPack(Path('путь_к_ресурсам') / 'tasks.json')
# Показать участнику только условие и открытую шкалу:
task = pack.public_task('task_01')
# Вызвать после окончательной отправки:
result = pack.evaluate('task_01', participant_prompt)
print(result['score'])
print(result['criteria'])
```

Передавайте абсолютный путь, рассчитанный относительно папки приложения/ресурсов,
а не текущей рабочей директории. Для PyInstaller включите tasks.json в данные сборки.
Не запускайте CLI из приложения через subprocess: вызывайте `pack.evaluate()` напрямую.

Метод возвращает JSON-совместимый словарь: итог, 7 критериев, объяснения,
доказательства с позициями символов, рекомендации, флаги и версии.
Он не принимает имя участника: имя и результат связывает само приложение/БД.
Неизвестный task_id вызывает KeyError; текст длиннее 6000 символов — ValueError.
Пустой текст допустим и получает 0, но интерфейс может запрещать его отправку.

Для хранения результата в будущей БД сохраняйте task_id, engine_version,
pack_version, pack_sha256 и весь результат. Хеш относится к точным байтам JSON.
Это позволит узнать, какой набор правил применялся к конкретной попытке.
Не меняйте правила в середине мероприятия: результаты разных версий не обязаны совпадать.

## Редактировать задания

У каждого задания устойчивый id: task_01…task_30. Можно менять условие, словари
`aliases` и примеры. После изменений проверяйте тесты и обновляйте pack_version.
Новые синонимы задаются словами: `адрес*`, `что произошло`, `номер для связи`.
Звёздочка допускается только в конце слова. Произвольные регулярные выражения не принимаются.
Задание этой версии должно иметь четыре поля с весами 10,10,15,15.
Для другой шкалы потребуется изменить и алгоритм, и проверку схемы.
