# Проект шкалы до 100 баллов

Статус: согласуемая спецификация, а не готовый алгоритм. Рабочая версия приложения пока считает по старой формуле.

## Открытая шкала для участника

| Критерий | Максимум | Что нужно описать |
|---|---:|---|
| Сбор данных | 25 | Четыре нужных поля — по 5; явное получение значений от пользователя — ещё 5 |
| Итоговая карточка | 20 | Создание карточки — 10; включение всех четырёх собранных значений — 10 |
| Порядок работы | 15 | Сбор до результата — 5; завершение только при наличии всех обязательных данных — 5; показ сотруднику — 5 |
| Проверка корректности | 15 | Указание проверять данные — 5; конкретная разумная проверка поля — 5; сообщение об ошибке и повторный запрос исправленного значения — 5 |
| Пропущенные сведения | 15 | Запрос недостающего — 5; сохранение уже известных значений и уточнение только пропусков — 5; запрет выдумывать данные — 5 |
| Подтверждение и исправление | 10 | Предпросмотр и подтверждение до завершения — 5; исправление выбранного значения, обновление карточки и повторное подтверждение — 5 |
| **Итого** | **100** | **Основной сценарий — 60; обработка данных и взаимодействие — 40** |

Примеры разумной проверки: возраст — целое неотрицательное число; количество — положительное целое; дата — существующая календарная дата; обязательное имя — не пусто и не состоит только из пробелов. Достаточно одной конкретной проверки любого поля задания. Точный формат телефона, максимальный возраст, рабочие часы и наличие мест не являются скрытыми требованиями. Не требовать их для максимума.

Короткие условия сами по себе не содержат всех критериев: общая инструкция и эта шкала обязательно доступны до начала попытки. Нельзя снимать баллы за неоговорённые функции, длину, стиль, отсутствие Markdown или незнание программирования. Одна ясная фраза может покрыть несколько действительно разных требований; повторение не даёт дополнительных баллов.

## Принципы будущего оценщика

- Каждый атомарный пункт имеет максимум и доказательство из текста.
- За одно поле — не больше 5. Перечисление названий без намерения получить значения от пользователя не закрывает сбор.
- Конкретная проверка связывает поле и допустимость значения; обработка ошибки связывает условие с действием. Россыпь ключевых слов не является доказательством.
- Показ карточки оценивается только в порядке работы, не повторно в результате. Сбор отдельных полей не подменяет проверку порядка.
- Если итог явно разрешён до получения всех обязательных сведений, соответствующие 5 за завершение не начисляются.
- Если требование одновременно дано и запрещено, спорный подпункт не засчитывать автоматически; отправить на ручную проверку. Не обнулять остальные независимые пункты.
- Не приравнивать нераспознанный синоним к доказанному отсутствию требования. Для неопределённых случаев предусмотреть пересмотр.
- Не штрафовать за смысловое совпадение с заданием: участник обязан использовать заданные сущности. Точную копию без собственной инструкции помечать для проверки, а не вводить произвольный штраф.
- Пустой ответ — 0. Результат детерминирован для одной версии правил.
- На первом этапе эта шкала пригодна для ручной оценки. Автоматическая смысловая проверка ещё не реализована; текущий словарный модуль её не обеспечивает.

## Скорость и рейтинг

Итог = сумма подпунктов, от 0 до 100. Нет множителя ×10 и нет бонуса минут.
При равном результате сравнивать длительность в миллисекундах; при полном равенстве место общее.
10 минут — ограничение попытки, а не часть качества промпта.

## Почему максимум должен стать менее частым

Минимальная инструкция «запроси поля и покажи карточку» не описывает проверку ошибок, работу с пропусками, подтверждение и исправление. За счёт этого возникает запас до максимума, а не искусственный штраф.

Не гарантируем заранее долю максимальных результатов. Если все участники выполнили все объявленные требования, все имеют право на 100. Нельзя вводить квоту на максимум, случайность или понижать баллы задним числом ради распределения.

Перед конкурсом собрать пробные ответы, оценить вручную, сравнить с будущим оценщиком и посмотреть распределение. Проверять также ошибочные, короткие, перефразированные ответы и ответы с противоречиями. Изменять задания и правила только между мероприятиями с повышением версии.
